# NittanyAuction

A course team project implementing an auction marketplace with Flask, SQLite, HTML, CSS, JavaScript, and Socket.IO. Users can browse categories, search listings, bid, manage seller listings, watch auctions, exchange messages, and submit helpdesk requests.

## Run locally

Requires Python 3.10+. From the project root:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/populationScript.py
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
export ADMIN_PASSWORD="choose-a-private-demo-password"
python app.py
```

Open http://127.0.0.1:5000. On Windows, set the two variables using `set SECRET_KEY=...` and `set ADMIN_PASSWORD=...` in Command Prompt, or `$env:SECRET_KEY=...` in PowerShell. The database is regenerated by the population script. The sample account credentials are in the synthetic `datasets/Users.csv` file.

## Features

- Bidder, seller, and helpdesk roles; registration and login
- Hierarchical category browsing, keyword search, and seller listing management
- Turn-based bidding with live auction notifications, watchlists, and messaging
- Mock checkout records, seller ratings, and category requests

## Layout

- `app.py`: Flask routes, database queries, and Socket.IO handlers
- `scripts/schema.sql`: SQLite schema; `scripts/populationScript.py`: database initialization
- `datasets/`: original synthetic course demonstration CSVs
- `templates/` and `static/`: server-rendered pages and assets

## Data and security scope

The included CSVs are synthetic course data, as confirmed by the project owner. They contain realistic-looking email addresses, account passwords, card numbers, security codes, and banking fields, so do not reuse any of these values for real accounts. Do not enter real card or banking information into the app. Payment processing is simulated; this academic prototype is intended only for local demonstration. Password hashing uses SHA-256 as originally implemented and is not suitable for a production authentication system. Do not deploy it publicly without redesigning authentication and payment handling.

The Flask session key and helpdesk password come from environment variables. Helpdesk registration is disabled unless `ADMIN_PASSWORD` is set. Keep `.env` and generated databases out of Git.
